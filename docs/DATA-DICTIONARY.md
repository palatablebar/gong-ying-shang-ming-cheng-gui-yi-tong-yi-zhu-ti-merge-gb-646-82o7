# 数据定义 供应商主数据台账

## 输入列契约

| 列名 | 别名 | 类型 | 可空 | 说明 |
|---|---|---|---|---|
| `supplier_id` | 供应商编码、供应商号 | 字符串 | 否 | 来源系统内的记录号，保形不去零 |
| `supplier_no` | 供应商编号、编码 | 字符串 | 否 | 集团编码，前导零保留 |
| `name` | 名称、供应商名称 | 字符串 | 否 | 原始名称，至少 4 字 |
| `tax_id` | 税号、纳税人识别号 | 字符串 | 是 | 空串表示确实没有税号，哨兵另记标记 |
| `city` | 城市 | 字符串 | 是 | 用于城市不一致降级判定 |
| `bank_account` | 开户行账号 | 字符串 | 是 | 保形，仅作证据 |
| `erp_source` | 来源系统 | 字符串 | 是 | ERP-A 到 ERP-D |
| `ref_master_id` | 主档号 | 字符串 | 是 | 声明本记录归属的主档，需通过引用核验 |
| `ytd_amount` | 本年累计 | 十进制 | 是 | 单位元，两位小数，Decimal 存储 |
| `last_update` | 更新时间 | 日期 | 是 | 来源系统日期，不参与计算 |

## 批次标识

- `run_id` 由输入摘要（按文件名排序的 sha256 拼接）与规则版本共同取摘要，
  因此同一批文件重跑得到同一个批次，规则版本升级后同输入会生成新批次。
- 运行清单同时保留每个文件的 sha256、字节数、编码与分段数。

## 空值与哨兵

- `null` 与空串：字段确实没有值，例如空税号表示该供应商未登记税号。
- 哨兵：`-`、`--`、`n/a`、`na`、`null`、`none`、`未知`、`无`、`空`、`/`，
  只在 `app/config.py` 的 `SENTINEL_VALUES` 定义一次。
- 税号哨兵记为 `F_TAX_SENTINEL`，金额哨兵记为 `F_AMOUNT_SENTINEL` 并落 0.00；
  两者都不进入税号比对，但会出现在导出的标记列里。

## 数值

- 金额与合计一律 `Decimal`，最小刻度 0.01，对外 JSON 与 CSV 用字符串。
- 簇内分摊：按成员金额比例，取整到分后用最大余额法补齐，合计恒等于簇金额。
- 比例与得分保留 6 位小数，权重 0.55 与 0.45 定义在 `app/config.py`。

## 时间

- 采集时间与复核时间一律 UTC 存储（`YYYY-MM-DDTHH:MM:SSZ`），页面显示 `+08:00`。
- 复核查询时间窗为左闭右开 `[since, until)`：`since <= decided_at < until`。

## 名称归一规则

| 编号 | 规则 | 示例 |
|---|---|---|
| N01 | 全角转半角 | （北京） → (北京) |
| N02 | 括号统一 | 〔北京〕 → (北京) |
| N03 | 去空白 | 鼎新 科技 → 鼎新科技 |
| N04 | 去法律后缀 | 有限公司 / 股份有限公司 / 集团 / 控股 / 公司 |
| N05 | 去地名标记 | 北京鼎新科技 / 鼎新科技(北京) → 鼎新科技 |
| N06 | 拉丁小写 | ABC → abc |
| N07 | 去标点 | 残留标点与空括号 |

行业词（物流、贸易、建材、化工等）不剥离，避免把不同主体并到一起。

## 相似度与分档

- bigram Dice = 2 × |A∩B| / (|A| + |B|)，A、B 为归一名的相邻两字集合。
- 编辑比率取 `difflib.SequenceMatcher(None, a, b, autojunk=False).ratio()`。
- 得分 = 0.55 × Dice + 0.45 × 比率，量化到 6 位。
- 分档：得分 ≥ 0.92 自动合并；0.80 ≤ 得分 < 0.92 人工复核；其余拒绝。
- 判定优先级：税号冲突（拒绝） > 税号相同（自动） > 城市不同（复核） > 得分分档。

## 主体与代表元

- 并查集合并顺序无关，根取字典序较小的供应商号。
- 代表元 = 簇内税号最小者；无税号时取供应商号最小者。
- 簇编号按 (税号, 代表号) 升序分配。
- 簇内出现两个以上非空税号记 `CLUSTER_CONFLICT`，该簇不参与自动合并。

## 去重键与空态

- 去重键为 `supplier_id`；同键同值剔除并记 `Q_DUP_ID_SAME`，同键不同值进冲突表。
- 空态三态：仅表头 `header_only`、全空行 `blank_rows`、无数据行 `no_row`，
  三者在文件诊断里分别给出，不合并成同一个成功结论。

## 付款批次（M8）

### 输入列契约

| 列名 | 别名 | 类型 | 可空 | 说明 |
|---|---|---|---|---|
| `line_no_src` | 行号、来源行号 | 整数/字符串 | 否 | 来源系统物理行号，参与行键 |
| `supplier_id` | 供应商号、供应商编码 | 字符串 | 否 | 必须存在于名录主数据，否则隔离 |
| `supplier_name` | 名称、供应商名称 | 字符串 | 是 | 与主数据名称不符只预警不阻断 |
| `doc_no` | 单据号、发票号 | 字符串 | 是 | 参与行键 |
| `line_type` | 行类型、类型 | 字符串 | 是 | 应付/退款抵扣；留空按金额符号判定 |
| `amount` | 金额、发生额 | 十进制 | 否 | 应付为正、抵扣为负，零值隔离 |
| `currency` | 币种 | 字符串 | 是 | 默认 CNY |
| `remark` | 备注 | 字符串 | 是 | 证据字段 |

### 批次与行键

- 付款批次号 `PAY-xxxxxxxxxxxx` 由（文件名 + sha256 排序拼接）与 `PAY_RULE_VERSION`
  共同取摘要，独立于名录 `run_id`，同批重跑得到同一批次号。
- 行键 `PL-xxxxxxxxxxxxxxxx` 是源文件、物理行号、供应商号、单据号、类型、金额的
  内容指纹；重跑时键稳定，是核销决定的锚点，重复行键按 `W_LINE_KEY_DUP` 隔离。

### 抵扣归属与状态机

- 抵扣行按 `supplier_id` 锁回该记录所在的合并簇；主数据无此供应商即隔离
  `W_SUPPLIER_UNKNOWN`，未核抵扣不会减到别的主体。
- 状态：`pending`（待核，不抵减）、`approved`（已核销，参与抵减）、
  `rejected`（驳回，永不抵减）、`blocked`（主体税号冲突/名称异常挂起）。
- 阻断：税号冲突簇的抵扣 `W_CLUSTER_CONFLICT` 只能驳回不能核销；
  应付行名称不符记 `W_NAME_MISMATCH` 预警，不阻断付款。
- 可付净额 = 应付合计 + 已核销抵扣（负数）；待核/阻断/驳回抵扣只在未核列披露，
  一律不进净额。净额为负另记 `W_NET_NEGATIVE`。

### 核销与幂等

- 核销动作 `approve` / `reject` 带 `expected_version` 乐观锁，陈旧提交返回 409。
- 核销决定存 `payment_writeoffs`，与付款行 `payment_lines` 分离；重跑只替换行，
  按行键接回历史决定，已确认归属与净额不被改变、不重复计入。
- 页面、主数据导出 `master.csv` 净额列、`reconcile()` 三处净额同源，逐分相等。
